# 渐进式创作与版本语义

> 来源：连续对话和真实试听反馈
>
> 状态：需求已确认，待调研与设计

## 用户反馈

当前自然语言交互过于接近“一次输入、一次完整交稿、一个新版本”：

1. 每次自然语言输入只要生成了不同且校验通过的乐谱，就立即成为新版本；对话轮次与作品版本过度绑定；
2. 模型倾向一次生成较短的完整篇章，材料发展和整体效果不佳；后续自动修正主要解决语法、时长和乐器
   约束，不能把薄弱的音乐内容修正为成熟作品。

这两个现象来自同一个缺口：系统只有“对话”和“有效版本”，缺少创作计划、可试听草稿和待接受候选等
中间状态。

## 当前事实

并非所有输入都会创建版本：命令、空输入、澄清、失败、取消和与当前乐谱完全相同的结果都不会创建。
但所有普通自然语言都进入同一 Agent 生成流程；模型只要调用 `submit_alda` 提交不同乐谱并通过必要检查，
`Application` 就立即调用 `Project::save_version`。

当前实现还会强化一次性交稿：

- [默认创作策略](../../alda-agent/prompts/default-creative-strategy.md) 要求“提交一个完整候选”，并要求首次
  提交就规划足够内容和时长；
- [生成协议](../../alda-agent/prompts/protocol.md) 只允许通过 `submit_alda` 提交完整乐谱；
- Agent 的多轮循环实际是“完整乐谱 → 客观校验 → 修错”，不是材料、段落和整体结构的渐进创作；
- [Alda 校验](../../alda-agent/src/alda.rs) 只检查语法、非空内容、时长和乐器约束。这些检查是有效乐谱的
  必要条件，不是音乐质量充分条件；
- 当前作品显著短于目标时长时，反馈优先要求保持音符和段落不变、只缩放 tempo。这可能把内容不足的短篇
  拉长到目标时长，而没有补充材料发展，客观通过但听感进一步变差。

因此当前实际成功标准接近“可解析、非空、时长接近、乐器符合”，不能证明材料、结构或听感达到预期。

## 目标语义

后续设计必须分开以下概念：

| 概念 | 含义 | 是否改变当前有效版本 |
|---|---|---|
| 对话轮次 | 用户提问、讨论、反馈或创作要求，以及 Agent 的回答 | 否 |
| 创作计划 | 对素材、曲式、配器和发展方式的文字方案 | 否 |
| 素材草稿 | 可生成、校验和试听的局部材料或未完成作品 | 否 |
| 完整候选 | 已组装并通过必要客观检查、等待试听判断的作品 | 否 |
| 有效版本 | 用户选择保留的、有意义的作品节点 | 是 |

目标流程是：

```text
用户意图
  → 普通回答 / 澄清 / 创作计划
  → 核心材料或分段草稿
  → 逐步发展和组合
  → 完整候选
  → 客观校验
  → 试听与反馈
  → 接受为有效版本，或继续修改/放弃
```

系统不应把“不调用乐谱工具的模型文本”一律解释成澄清问题，也不应把每个校验通过的不同乐谱自动解释成
有效版本。Agent 至少需要明确表达普通回答、请求澄清、提出计划、产生草稿和提交完整候选等不同结果。

## 创作质量要求

- 不再要求首次模型调用必须完成整首作品；允许先确认方向、建立核心材料，再发展段落和整体结构；
- 草稿可以不满足完整曲目的目标时长，但必须明确其范围和用途，不能冒充完整候选；
- 完整候选仍必须通过语法、内容、项目时长和乐器约束等客观检查；
- 显著过短通常意味着内容量或结构不足，不能默认只靠降低 tempo 达标；应结合用户意图补充或发展材料；
- 事件数、声部数、源码长度和重复次数只能用于诊断，不能作为音乐质量评分；
- 最终质量判断保留真实试听反馈，程序不得把客观校验通过表述为艺术质量已经合格。

## 设计边界

下一步设计应先确定最小可用的候选生命周期、Agent 结果类型和试听/接受交互，再决定持久化布局及命令。
当前不预设：

- 草稿和候选是否全部持久化，或只保留当前候选；
- 使用自然语言接受候选，还是增加显式命令；
- 首个有效版本是否允许自动接受；
- 是否支持并列候选、分支版本或通用工作流引擎。

不应先引入多候选、分支、后台任务或复杂状态机。首个方案只需证明对话不再自动等于修改、候选不再自动
等于版本，并能支持一次真实的渐进创作与试听反馈闭环。

## 完成判定

- 普通问答、方案讨论和澄清不会修改乐谱或创建版本；
- 用户可以先获得并试听草稿或完整候选，再决定继续修改、接受或放弃；
- 连续多轮发展同一个候选时，版本历史不会按对话轮次膨胀；
- 只有被接受的完整候选才能成为有效版本并更新 `current.alda`；
- 短而内容不足的候选不会仅靠 tempo 拉伸变成“成功作品”；
- 至少用一次真实素材完成“计划 → 草稿 → 发展 → 完整候选 → 试听反馈 → 接受版本”的终端验收。
