# 分级开放工具并行调用

## 背景

当前模型请求显式发送 `parallel_tool_calls: false`。供应商仍返回多个工具调用时，宿主拒绝整批调用并要求模型重试。这保证了 `submit_result` 的唯一终止语义，也避免有副作用工具在部分成功后难以恢复，但会让多个相互独立的只读查询被迫串行执行。

## 目标

在不削弱结果提交、状态持久化和副作用边界的前提下，允许安全的只读工具并行执行：

- `submit_result` 必须独占一次模型响应；同轮出现其他调用时拒绝整批。
- `lookup_alda_docs` 及基于同一不可变快照的只读检查可以并行。
- `render_score`、`play_score` 等有副作用或依赖可变状态的工具保持串行。
- 合法的只读并行调用分别返回与 `tool_call_id` 对应的结果，不消耗协议恢复额度。
- 并行批次中的参数错误按调用分别返回；不得因部分失败重复执行已经成功的副作用操作。

## 验收条件

- 两个独立只读调用可以在同轮完成，并将两份结果正确写回模型上下文。
- `submit_result` 与任意其他调用并存、多个 `submit_result` 并存时均不会执行。
- 有副作用工具不会并行执行。
- 现有单工具调用、协议恢复、失败 revision 保存和候选提交行为不回归。
- 架构文档同步说明工具分类与调度规则。
