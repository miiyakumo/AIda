# Workflow 产物与 Agent 角色派生

> 已完成基础：[可组合指示系统首期](../iter/composable-instructions/README.md)
>
> 运行证据：[长篇叙事作曲 Agent 两次运行分析](../iter/long-form-composition-agent-diagnosis/README.md)
>
> 状态：长篇作曲已触发任务专用 A/B 原型；尚未实现或证明收益

## 结论

第二次五分钟创作在 Marker、form_plan 和 checkpoint 落地后仍用了 20 次模型调用、19 次工具往返和 3 次
协议恢复。模型一边设计动机、和声与织体，一边手算拍数、修 Alda 语法、维护 Marker 和组装提交参数，最终
仍出现短句高倍率展开、跨段溢出与游标回跳。这已经足以启动一个**长篇作曲专用、可撤回的最小 A/B 原型**。

该判断不等于采用通用 Multi-Agent 平台，也不证明 subagent 能提高作品质量。当前只验证一个具体假设：把
艺术设计、段落实现、确定性组装和独立复核分开，能否减少职责切换与 DSL 错误，并让主题发展更可定位。

## 当前边界

现有系统仍由单 Agent 完成正式创作，Project 是工作乐谱、恢复候选、版本和 form_plan 的唯一持久事实来源。
尚未实现 Role、fork、通用 Workflow、外部 Skill 脚本或多分支乐谱。

Marker/form_plan 已解决段落位置和覆盖的可观测性，但没有解决：

- form_plan 缺少精确动机、和声区域、织体和变形关系，容易事后回填；
- 模型拍数换算错误可让声部越过下一 Marker，再由 `@section` 向后跳造成重叠；
- 同一上下文同时承载作曲判断、Alda 编码、语法恢复和最终提交协议；
- Marker 对齐与事件数达标不能证明段落内部有发展。

因此原型要收紧任务边界，而不是抽象一套通用角色运行时。

## 最小 Brain–Worker–Reviewer 流程

```text
用户完整创作要求
        ↓
主 Agent / Composer
├── 精确音高与节奏动机
├── 和声与调性路线
├── 曲式和叙事职责
├── 织体与配器曲线
└── 主题变形关系
        ↓
  CompositionSpec
     ├──────────────┐
     ↓              ↓
主题家族 Worker    对比发展 Worker
Intro/A/A2/Coda    B/C/D
     └──────┬───────┘
            ↓
     Harness 确定性组装
            ↓
     独立只读 Reviewer
            ↓
     主 Agent 艺术判断
            ↓
     用户完整试听与接受
```

第一版固定两个 Worker，按**段落家族**拆分，不按乐器拆分。按乐器拆分会让主题、和声和织体关系横跨多个
Agent，增加同步成本；段落家族则让一个 Worker 对一组完整音乐功能负责。

主 Agent 不只写抽象情绪说明。它必须拥有并给出精确动机、和声路线、曲式职责、织体曲线与变形关系，确保
“像音乐家一样设计”能够成为可执行约束。Worker 负责把约束实现为 Alda 片段，并在交付前自行修到语法通过。

任何 Agent 都不自由拼接完整 Alda 源码。Harness 是唯一组装者，负责命名空间、Marker、声部游标、片段边界、
溢出检测、解析和最终候选持久化。Reviewer 只读检查实现是否符合规格，不接受版本，也不直接重写作品。

## 结构化产物

### CompositionSpec

主 Agent 持有的全曲设计，至少包含：

- 精确核心动机及其节奏、音高和稳定 ID；
- 调性中心、和声区域与必要的迁移路线；
- 段落顺序、叙事职责和时间预算；
- 织体密度、主导声部与配器曲线；
- 各主题再次出现时必须采用的变形关系。

### SectionContract

从 CompositionSpec 派生给某一段落家族的实现契约，至少包含：

- 时间或拍数预算；
- 精确动机引用及必须采用的变形；
- 调性/和声区域；
- 主导声部、织体密度和允许乐器；
- 与前后段的进入、退出和过渡约束。

### SectionArtifact

Worker 的交付物，至少包含：

- 命名空间隔离的 Alda 片段；
- 解析所得实际时长与声部覆盖；
- 动机及变形的使用声明；
- Alda 解析结果与稳定事件哈希。

### ReviewReport

Reviewer 的只读报告，区分机械事实和音乐判断：

- 契约字段是否能在最终组装事件中定位；
- 是否存在游标回跳、跨段溢出、意外重叠或命名冲突；
- 主题变形、和声路线和织体曲线是否按规格实现；
- 仍需由主 Agent 或用户听觉判断的问题。

这些产物第一版可以是本次运行内的结构化消息，不立即建设通用 Artifact 仓库。只有验证其生命周期需要跨轮、
重启或复用时，才将其纳入 Project 持久化模型。

## 权限与不变量

- Project 仍是工作乐谱、恢复候选、版本和持久产物的唯一事实来源；
- 主 Agent 决定艺术规格和是否根据审查返工，但不能绕过宿主校验或用户接受；
- Worker 只产出所属段落家族的片段，不写项目事实主体、不组装全曲、不接受版本；
- Reviewer 只读，不修改片段、不提交候选、不接受版本；
- Harness 唯一执行命名空间归一、确定性组装、Marker/游标检查、完整渲染和持久化；
- 内部按段分工不转化为用户逐段试听或逐段批准；用户仍完整试听并显式接受最终候选；
- 角色权限只能是宿主授权的子集，不能通过提示扩大。

## A/B 验收

使用相同或等价的 3–5 分钟叙事作曲任务，对比当前单 Agent 基线与最小角色原型。原型至少满足：

- 直接创作要求不再错误停在计划结果，用户无需输入“继续”；
- 协议恢复为 0；
- 不出现声部游标向后跳、跨段溢出或意外同声部重叠；
- 每个 Worker 将所属片段修到 Alda 语法通过只需 1–2 轮；
- CompositionSpec 中的主题变形和和声路线能在最终产物中定位；
- 总模型调用明显低于第二次基线的 20 次，或在相近成本下人工盲听 A/B 明显更好；
- 最终接受仍由用户完整试听决定，不用静态检查冒充艺术质量。

如果职责拆分只增加编排调用、规格漂移或合并冲突，而没有上述可测收益，撤回原型并保留现有单 Agent 流程。

## 明确不做

- 不建设通用 Multi-Agent、Workflow DSL、Provider 插件树或多角色市场；
- 不按乐器拆 Worker；
- 不让 Agent 自由拼接、覆盖或持久化完整源码；
- 不增加多个可竞争的工作乐谱事实主体；
- 不把内部段落拆分变成用户逐段审批；
- 不在 A/B 验证前宣称 subagent 已改善质量。
