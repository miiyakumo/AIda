# Alda Music Agent 首期实施计划

> 状态：实现与离线验收已完成；真实模型与人工听感待外部配置
>
> 日期：2026-08-05
>
> 需求基线：`docs/requirements/product-requirements.md`

## 1. 目标

以《机械硬盘之诗》为真实输入，交付一个可以在 Linux 终端中完成以下闭环的 Rust 程序：

```text
输入诗歌
→ DeepSeek 解读并生成 Alda
→ 工具检查和自动修正
→ 保存有效版本
→ 播放
→ 自然语言局部修改
→ 恢复和导出
```

计划只覆盖首期需求。每个切片都必须产生可以运行或可以直接验证的结果，不先建设通用平台。

## 2. 实施规则

1. 保持单个 Rust crate，直到真实边界证明需要拆分；
2. 先使用具体的 DeepSeek 客户端、Alda 命令封装和本地文件存储；
3. 第二个真实实现出现前不提取 Provider、Store 或 Tool 通用 trait；
4. 不引入 HTTP 服务、WebSocket、数据库、事件溯源或后台 actor；
5. 每个切片尽量在数天内完成，并独立通过格式、静态检查和测试；
6. 真实 API、播放和安装检查使用显式 smoke test，不让默认测试依赖网络或音频设备；
7. 原型证明假设错误时，先修订需求或计划，再增加复杂度。

- 启用 `unsafe_code`、`clippy::all` 和 `clippy::pedantic` 警告；

- 检查 Java、Alda、播放链、MIDI 导出和开发所需 Rust 工具链；
- 脚本不静默执行提权、不修改 shell 配置；
- 添加一份最小 Alda fixture，验证 `alda version` 和 `alda parse`。

### 预期产物

- `alda-agent/Cargo.toml`；
- `alda-agent/src/main.rs`；
- `alda-agent/scripts/install-linux.sh`；

- 默认 Rust 测试不需要网络或真实音频设备。

## 5. 切片 1：DeepSeek 真实连通实验

### 用户结果

程序能够把一段短文本发送给 DeepSeek，并在终端流式显示响应。

### 工作内容

- 从仓库根目录 `.env` 读取 `ALDA_AGENT_API_KEY`、`ALDA_AGENT_BASE_URL` 和 `ALDA_AGENT_MODEL`；
- 直接解析当前需要的 `KEY=VALUE` 配置，不建设通用配置系统；
- 支持可配置的 DeepSeek 模型标识；
- 用 `reqwest` 与 `serde` 实现实际需要的 OpenAI-compatible 最小字段；
- 验证流式文本事件和错误返回；
- 验证工具调用；若实际兼容性不足，验证一种稳定的结构化工具请求作为降级；
- 使用较长输出探测截断、结束原因和 token 限制；
- 记录一次请求中实际发送的字段类别，但不记录密钥或完整隐私内容；
- 首次真实请求前提示素材、要求、乐谱和错误会被发送到配置的模型服务；
- 为网络请求设置超时，并确认 `Ctrl+C` 可以取消当前流式请求；
- 区分认证失败、限流、网络错误、模型拒绝和输出截断，不把它们描述成作品问题。

### 预期产物

- `alda-agent/src/deepseek.rs`；
- 仓库根目录 `.env.example`，包含上述三项规范键的占位示例；
- DeepSeek 请求、流式事件和错误响应 fixture；
- 一个显式的真实 API smoke 命令；
- 一份不含凭据和完整素材的 smoke 结果摘要。

### 决策门

- 工具调用可靠时，首期直接使用它；
- 工具调用不可靠时，只实现一个经过 fixture 验证的结构化输出格式；
- 只有出现第二个真实模型后才提取 Provider trait；
- 长作品容易截断时，把分段创作列入后续切片；否则先保持一次生成。

### 完成条件

- 显式 smoke test 能收到真实 DeepSeek 流式响应；
- 固定响应 fixture 能在离线测试中复现文本、工具请求、结束和错误路径；
- 首次数据外发提示只在真正发出请求前出现；
- 用户取消后流式请求在有限时间内结束；
- API key 不出现在输出、项目数据或测试快照中，`.env` 已被 Git 忽略。

## 6. 切片 2：Alda 工具实验

### 用户结果

用户可以检查、播放、停止和导出一份本地 Alda 乐谱，并看到可理解的结果。

### 工作内容

- 封装固定的 Alda 命令，不接受任意 shell 字符串；
- 实现语法检查并保留 stderr 诊断；
- 验证 MIDI 导出；
- 验证播放和停止行为；
- 给子进程设置超时、取消和输出上限；
- 调研 Alda parse 数据能否可靠推导作品时长；
- 对指定和排除乐器实现简单检查；
- 为成功、语法失败、超时和缺少可执行文件编写离线或本地集成测试。

### 预期产物

- `alda-agent/src/alda.rs`；
- 合法、语法错误、空作品、无效乐器和多声部 Alda fixture；
- 一个显式的本机播放/MIDI smoke 命令；
- 时长推导实验及其固定输入输出记录。

### 决策门

- 时长能可靠推导时，输出实际时长和目标偏差；
- 时长无法可靠推导时，首期显示“未检查”，不能用模型估计冒充工具结论；
- 播放无法被 Alda 可靠停止时，先提供清楚的受限行为和手动恢复方法，再决定是否增加进程管理。

### 完成条件

- 合法 fixture 被判定为通过；
- 非法 fixture 返回可反馈给模型的结构化诊断；
- MIDI 文件能够生成；
- 用户取消后不留下本次启动的播放子进程；
- 检查结果只使用“通过、失败、未检查”。

## 7. 切片 3：第一个真实创作纵切片

### 用户结果

用户输入《机械硬盘之诗》，得到第一份通过必要检查的可播放 Alda 作品。

### 工作内容

- 支持终端多行输入和读取文本文件；
- 支持用户在自然语言中指定或排除乐器；
- 支持用户选择完整曲目或即兴片段，未指定时由 Agent 根据请求采用一个明确默认值；
- 构建首期系统提示和创作请求；
- 要求模型先输出简短解读、音乐构想和配器理由；
- 默认直接进入创作，不等待确认；
- 只有会显著改变作品方向的歧义才询问用户；
- 让模型通过工具请求提交 Alda 候选；
- 执行语法、截断、乐器和可用的时长检查；
- 检查失败时把真实诊断反馈给模型，最多自动修正 3 轮；
- 达到上限后，用户可以显式要求继续修正；
- 通过后保存 `current.alda`，并允许立即播放；
- 达到上限仍失败时保留诊断，不伪造成功。

### 预期产物

- `alda-agent/src/agent.rs`；
- 《机械硬盘之诗》和一份短即兴请求 fixture；
- 创作、工具反馈、三轮修正和显式继续的离线 transcript fixture；
- 一个真实 DeepSeek + Alda 的创作 smoke 命令。

### 完成条件

- 真实 DeepSeek 和真实 Alda 完成一次端到端创作；
- 完整曲目与即兴片段各至少成功生成一次；
- 指定乐器和排除乐器各有一个可观察的成功或明确拒绝结果；
- 用户不需要手工修复 Alda 语法；
- 成功结果可以从头到尾播放；
- 失败路径不会留下一个被宣称为有效的作品；
- 记录首次可播放结果的耗时、模型调用次数和修正次数，暂不设性能 SLA。

## 8. 切片 4：项目、版本与交互式修改

### 用户结果

用户可以退出后继续项目，按自然语言修改作品，并恢复任意有效版本。

### 工作内容

- 一个目录对应一个项目；
- 保存原始素材、明确要求、当前解读、当前版本和必要会话记录；
- 有效版本使用线性编号保存在 `versions/`；
- 失败草稿不进入普通版本历史；
- 实现交互式 REPL；
- 实现 `/history`、`/restore`、`/quit` 和手工源码重新采用命令；
- 支持整首、明确段落和明确乐器的自然语言修改；
- 范围不清楚时让模型先询问；
- 修改后重新执行必要检查，通过后创建新版本；
- 恢复旧版本只改变工作基线，不覆盖历史。

### 预期产物

- `alda-agent/src/project.rs`；
- 项目元数据、版本文件和会话记录的最小格式；
- REPL 命令解析与项目重启集成测试；
- 路径逃逸、损坏元数据和无效人工修改的负例。

### 建议的最小项目布局

```text
project-directory/
├── project.json
├── source.txt
├── context.json
├── current.alda
├── versions/
│   ├── 0001.alda
│   └── 0002.alda
└── exports/
```

布局可在实现时缩减，但不得引入数据库或事件日志框架。

### 完成条件

- 重启 CLI 后可以继续修改当前作品；
- 成功修改创建新版本；
- 失败修改不改变当前版本；
- 恢复旧版本后继续修改不会覆盖任何历史文件；
- 用户手工修改后必须显式重新读取和校验。

## 10. 每个切片的机械门禁

在 `alda-agent/` 中运行：

```bash
cargo fmt --all -- --check
cargo check --all-targets --all-features
cargo clippy --all-targets --all-features -- -D warnings
cargo test --all-targets --all-features
```

包含 shell 脚本的切片还应执行相应语法检查。真实 DeepSeek、Alda 播放和人工试听使用显式命令，
不能混入默认离线测试。

每个切片结束时还必须：

1. 更新本文对应切片的状态和实际验证命令；
2. 记录与计划不同的事实及采用理由；
3. 删除该切片不再需要的实验代码；
4. 确认没有引入第 12 节明确延后的能力。

## 11. 停止条件

出现以下情况时，暂停增加功能并回到需求或原型：

- DeepSeek 无法稳定产生可识别的完整 Alda 候选；
- Alda 无法可靠完成首期需要的解析、播放或 MIDI 导出；
- 2.5–4 分钟作品持续超出模型输出能力；
- 三轮自动修正仍不能闭合主要语法失败；
- 用户无法理解 Agent 的解读、检查结果或修改范围；
- 为完成当前切片需要引入多个新基础设施层。

停止不等于项目失败；它表示当前假设需要用更小实验重新验证。

## 12. 明确延后

以下内容不进入上述切片：

- 第二个 Provider 和通用 Provider trait；
- 默认多候选、分支、Take 和 A/B；
- Web、本地服务和协议层；
- 数据库、事件溯源和复杂恢复；
- Skill 框架、Plugin、Hook、MCP 和 Memory；
- 游戏 BGM、声乐谱曲、弦乐四重奏和交响曲专用工作流；
- WAV、MP3 和专业记谱输出。

它们只有在首期闭环给出真实需求证据后才重新规划。
