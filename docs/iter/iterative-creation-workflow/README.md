# 渐进式创作与版本语义

> 状态：代码闭环与机器控制面已完成，待主观试听验收
>
> 来源：[原始需求](../../todo/iterative-creation-workflow.md)

## 目标

以一个最小纵向切片解耦对话、工作乐谱和有效版本，支持：

```text
计划 → 草稿 → 发展 → 完整候选 → 试听反馈 → 接受版本
```

普通回答、计划和澄清只改变对话；草稿和完整候选只改变当前工作乐谱；只有用户明确接受完整候选时才创建
有效版本；`current.alda` 随后作为当前版本的可修复投影更新。

## 领域模型

项目至多持有一个工作乐谱 `work.alda`，其元数据保存在 `project.json`：

| 工作类型 | 含义 | 检查 | 可接受为版本 |
|---|---|---|---|
| `draft` | 用于试听和发展的局部材料或未完成作品 | 语法、非空内容、乐器约束 | 否 |
| `candidate` | 等待试听判断的完整作品 | 草稿检查加项目目标时长 | 是 |

新的草稿或候选覆盖旧工作乐谱，不保留并列候选或工作历史。接受候选后创建下一个单调递增的 immutable
version，并在同一次 `project.json` 提交中清除工作状态；放弃只清除工作乐谱，不改变当前有效版本。

## Agent 结果协议

模型每轮必须通过结构化结果明确返回以下一种类型：

- `answer`：普通回答；
- `clarification`：需要用户补充的信息；
- `plan`：文字创作计划；
- `draft`：可校验、试听和继续发展的 Alda 草稿；
- `candidate`：完整 Alda 候选。

文本结果不调用 Alda。草稿忽略整曲目标时长；候选执行全部必要检查。检查失败可以在同一次请求中自动修正，
但不得改变结果类型。显著过短的候选应补充和发展音乐材料，不再默认通过降低 tempo 拉伸。

## 交互

- 自然语言用于讨论、计划、生成和继续修改当前工作乐谱；
- `/alda play work` 试听工作乐谱；默认 `/alda play` 仍播放当前有效版本；
- `/alda check work` 重新检查工作乐谱；草稿仍跳过整曲时长，完整候选执行全部检查；
- `/project accept` 接受检查通过的完整候选；
- `/project discard` 放弃当前工作乐谱；
- `/project` 同时展示当前有效版本和工作乐谱状态。

首个候选也不自动接受。接受和放弃使用显式命令，避免把自然语言误判为不可逆的版本操作。

## 持久化布局

```text
project-root/
├── project.json       # 规范元数据，含单个 working_score
├── work.alda          # working metadata 引用的规范工作源码，可选
├── current.alda       # 当前有效版本投影，可选
└── versions/          # immutable 已接受版本，规范源码
```

已接受版本由 `project.json` 和其引用的 immutable version 源码共同定义，`current.alda` 是可修复投影；
工作状态由 working metadata 与其引用的 `work.alda` 共同定义，源码缺失即损坏。加载项目时会修复
`current.alda`、清理协议命名的未提交版本，并仅在 working metadata 已清除时删除残留 `work.alda`。
项目尚未发布，本次直接更新元数据格式，不增加迁移层。

## 完成判定

- 五种 Agent 结果在协议和应用结果中可区分；
- 多轮更新工作乐谱不增加版本，重启后工作状态仍存在；
- 草稿可在未达到整曲时长时通过并试听，但不能接受；
- 完整候选通过全部检查后仍不自动创建版本；
- 接受是 Agent 候选成为有效版本的唯一入口，`/project adopt` 仍保留为显式采用外部文件的入口；
- 自动化测试覆盖计划、草稿、发展、候选、接受和重启；真实终端试听作为最终人工验收。
- JSONL 控制面可直接驱动真实模型、Alda、项目动作并读取结构化事件和快照，不再要求人工代为操作程序；
  最终人工验收只保留音乐听感和意图符合度等主观判断。

## 实施与验证结果

已完成领域状态、Agent 结构化结果、应用动作、终端提示、持久化与离线端到端测试。一次性 `compose` 只会
输出完整候选；若模型返回计划、澄清或草稿，会以非零退出引导进入交互模式。子进程测试锁定 stdout、
退出状态、输出文件和主要失败文本合同。

自动化验证已通过：

- `cargo test --all-targets`；
- `cargo clippy --all-targets --all-features -- -D warnings`；
- `cargo +1.85.0 check --locked`。

离线纵向测试覆盖“计划 → 草稿 → 发展为完整候选 → 重启恢复 → 显式接受 → 版本 1”。尚需用真实模型和
真实 Alda 完成运行验证，并试听确认音乐发展质量符合预期。其中真实程序流转可由 `control` JSONL 接口
自动执行和记录，试听判断仍由用户完成。
