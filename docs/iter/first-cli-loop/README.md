## 需求范围

首期验证“用户能否把非音乐素材通过自然语言发展成可播放、可修改、可恢复和可导出的器乐作品”。
范围限定为 Linux 上的单进程 CLI/REPL、一个显式配置的模型服务和本机 Alda，不包含 GUI、服务端、
数据库、多候选、分支版本或通用 Skill/Provider 框架。

核心闭环为：

```text
素材与要求 → 模型解读和创作 → Alda 候选 → 客观校验与自动修正
→ 有效版本 → 播放/试听 → 自然语言修改 → 新版本 → 恢复与导出
```

## 当前结论

首期所需的程序路径已经实现。离线测试覆盖了创作、修改、版本、恢复、导出和重启的纵向流程；当前
机器上的真实 Alda 链也通过解析、时长、乐器、MIDI、播放和停止 smoke，代码质量门禁全部通过。

用户补充确认，真实 REPL 创作和主观验收此前已经完成：使用真实素材和 180 秒目标保存版本 1，提出
可观察的自然语言修改后保存版本 2，并验证历史、恢复、Alda/MIDI 导出和重启继续；随后从头到尾试听
两个版本，完成作品可听性、修改效果和未要求部分保持度的主观判断。因此首期产品验收可以关闭。

本次验收的明确产品反馈是：**当前 CLI 交互过于简陋，不符合人体工程学。** 这不再是首期闭环的
阻塞项，而是验收产生的下一阶段核心需求，见[CLI 交互体验改进](../../todo/cli-ergonomics.md)。
