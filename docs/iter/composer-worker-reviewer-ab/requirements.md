# 长篇作曲角色实验需求

> 本文保存 2026-08-18 的实验期需求。第 9 条隔离要求已在实验成功后由 2026-08-19 的产品决策解除；
> 角色中间产物仍不进入 Project，只有最终完整候选进入统一工作乐谱闭环。

## 背景

现有单 Agent 能完成五分钟 Alda 候选，但多次真实运行显示，它在同一上下文中同时承担音乐设计、时长换算、
Alda 编码、语法修复和提交协议，注意力容易从听觉结果转向可机械打勾的指标。首次 Composer–Worker–Reviewer
A/B 又证明，简单拆角色并不能自动改善结果：Composer 在协议恢复后仍只声明出 37.14 秒时间线，角色臂没有
进入 Worker。

本需求不是建设通用 Multi-Agent 平台，而是验证一个长篇作曲专用假设：将音乐决策与 Alda 实现分开，同时
继续以 Alda 作为唯一的音乐片段、声部和时间线语言，能否降低职责切换与 DSL 错误，并产生可完整试听的作品。

## 功能需求

1. Composer 负责全曲的音乐设计，包括速度、拍号、曲式、段落相对比例、动机、和声、织体、配器和发展关系；
   不编写 Alda，也不手算全曲绝对拍数。
2. 第一版固定两个 Worker，并按段落家族分工。每个 Worker 实现所属段落的全部声部，不按乐器拆分。
3. Worker 直接交付受限的原生 Alda sequence 内容；Alda 的变量、序列、反复、parts、voices、rests 和 Marker
   继续承担音乐片段复用与时间线执行。
4. Harness 根据目标时长、Composer 选择的速度/拍号和段落比例，确定性地产生每段预算；预算一旦发给 Worker
   就不可由 Worker 修改。
5. Harness 使用固定 Alda 模板连接 Worker 片段，生成无命名冲突、可读、可解析的完整 Alda，不建立第二套
   音乐语言或运行时。
6. 每个 Worker 产物和最终合并产物都必须经过真实 `alda parse`。宿主验证语法、段落边界、各声部游标、
   越界和总时长，技术失败最多返工一次。
7. Reviewer 只读审查 Composer 计划、最终 Alda 和真实解析事实；它不能修改源码、持久化候选或接受版本。
8. 角色臂必须最终生成 Alda、MIDI 和完整 WAV，才能与现有单 Agent 做作品 A/B；用户仍依据完整试听显式接受。
9. 实验入口与正式 `Application`、`Project` 和版本事实主体隔离。实验成功前不得接入正式创作流程。

## 时间精度定义

“精确时间线”指 Harness 选定音乐网格后，段落起止和每个声部游标能由真实 Alda Marker offset 精确复核。
用户给出的“约五分钟”先量化为合法的小节或乐句网格，实际计划时长必须明确报告，不靠隐藏休止或扩大循环
伪装达标。

游标边界、最后一个可听事件和 WAV 尾部是不同事实：Alda 默认 quantization、延音和渲染尾音可能让 WAV
时长不同于声部游标。宿主分别报告这些值，不把其中任何一个冒充全部时间语义。

## 音乐判断边界

宿主只检查可确定判定的事实。主题是否有记忆点、和声是否有效、织体是否清晰、对位是否自然以及风格是否
到位，由 Composer、Reviewer 和用户试听判断。

第一版不增加对位专用类型、平行五八度规则、自动和声评分或通用材料识别器。只有某类问题在多个真实任务中
反复出现、能够从 Alda 事件稳定判断且误判风险可接受时，才单独评估可选分析能力。

## 权限与事实主体

- Project 仍是工作乐谱、恢复候选、版本和用户接受状态的唯一事实主体。
- Composer 和 Worker 只能提交各自的结构化结果，不能写 Project 或接受版本。
- Harness 只拥有实验输出目录、Alda 解析/渲染和确定性代码生成权限。
- Reviewer 只有读取计划、源码和解析摘要并提交报告的权限。
- 内部段落分工不转化为用户逐段批准；最终仍只有一个完整候选。

## 验收要求

- Composer 不再提交 `duration_beats`，不会因全曲拍数求和失败而阻止 Worker 启动。
- 同一输入的预算分配和 Alda 模板输出确定一致。
- 片段短一拍、长一拍、缺失声部、Marker 注入、命名逃逸和时间回跳均会在渲染前失败。
- 两个 Worker 各自在初次提交或唯一一次技术返工后通过真实 Alda 检查。
- 角色臂生成完整、非静音、目标时长范围内的 WAV。
- 记录两臂的模型调用、协议恢复、耗时、Alda 事件、时长和失败原因。
- Marker、事件数、RMS、Reviewer 批准都不表述为音乐质量通过；质量比较必须保留完整人工试听。

## 明确不做

- 不建设通用 Workflow DSL、Artifact 仓库、角色市场或递归 subagent 树。
- 不建设 Alda 之上的函数式片段语言、通用 Timeline DSL、声部调度器或自定义音乐运行时。
- 不按乐器拆 Worker，不引入多个可竞争的工作乐谱或版本分支。
- 不让 Harness 自动续写旋律、决定和声、修补织体或为凑时长重复材料。
- 不增加对位专用机制、通用审美打分或逐段强制试听。
