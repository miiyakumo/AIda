# 终端信息分层改造

> 需求来源：长会话中会话历史、输入栏、活动/播放状态和项目信息难以分辨
>
> 外部调研：[Coding Agent 的终端信息分层](../../research/coding-agent-terminal-information-layout.md)
>
> 方案与实施日期：2026-08-13
>
> 状态：实施完成，自动化与真实终端渲染验证通过

## 目标

在保留 reedline 和终端原生 scrollback 的前提下，让不同生命周期的信息拥有不同位置：

- 历史保留已提交的用户输入、模型输出、工具结果和最终结果；
- 活动 spinner 继续只占临时行，完成后不残留重复状态；
- 项目摘要和下一步状态只属于当前输入块，不复制到滚动历史；
- 输入始终以 `›` 标识，多行续行以 `·` 标识；
- 当前有效版本属于“项目”行，已发起播放的版本属于“状态”行，不再混成一个状态。

本次不引入全屏 TUI、alternate screen、焦点管理或后台任务队列。当前操作串行，固定底部 composer
尚无对应需求；reedline 的自定义 prompt 已能提供所需边界。

## 调研结论与取舍

Codex CLI、Claude Code 和 Grok Build 都把界面分成会话历史、活动状态、输入区和环境上下文四种概念，
区别主要在渲染技术。共同点是不会把稳定上下文和临时状态在每轮都固化进历史。

alda-agent 采用这个信息模型，但不复制它们的全屏 TUI：

```text
› /project versions                 已提交输入，永久进入历史
尚无有效版本                        动作结果，永久进入历史

项目 · poem · v2 · 完整曲目         当前项目上下文，只存在于活动输入块
状态 · 已发起播放 v1 · /alda stop   当前会话/播放状态，只存在于活动输入块
›                                   下一次输入入口
```

该取舍保留终端的复制、搜索和滚动能力，同时消除原实现每轮无条件 `println!` 项目摘要与下一步所造成的
重复。完整项目事实仍只由 `/project` 展开。

## 实施计划与结果

1. **建立输入块边界**：实现 reedline 自定义 `InputPrompt`，用 `项目 ·`、`状态 ·` 和 `›` 建立稳定层级；
2. **清理滚动历史**：启用 reedline transient prompt，提交时把当前项目和状态重绘掉，只留下 `› 用户输入`；
3. **保持活动状态临时**：继续由 `TerminalReporter` 管理 spinner，模型文本或阶段结果出现前清除 spinner；
4. **验证状态归属**：测试“项目 v2、播放 v1”的组合，确保两者分别出现在项目行和状态行；
5. **验证真实终端**：用 PTY 覆盖宽、窄终端和多行粘贴，再用 tmux 捕获五轮交互后的实际 scrollback。

实现集中在 `alda-agent/src/repl.rs`，没有改变 `Application`、`ProjectView` 或 `ConversationView` 的事实
来源，也没有新增 UI 框架或依赖。

## 验收证据

- `cargo test`：通过；
- `cargo clippy --all-targets --all-features -- -D warnings`：通过；
- `cargo +1.85.0 check --locked`：通过；
- PTY 测试验证 100 列和 32 列终端均保留项目、状态和输入标记，多行粘贴仍只提交一次；
- tmux 100×32 终端连续提交五条命令后，scrollback 中有 5 个 `›` 输入锚点，只有当前输入块各有 1 个
  `项目 ·` 和 `状态 ·` 标记。

这证明空输入或连续操作不会继续把项目摘要和状态复制进历史；终端变窄时文本可自然换行，但三个主要
标记仍保留，输入内容不会因布局降级而丢失。
