# 审议式执行

以"需求—设计—执行—验证—复核"的闭环完成复杂任务。不提供步骤清单——Agent 应根据任务自行判断每个环节的深度和形式。

## 核心信念

审议式执行基于三条信念，所有规则是它们的推论，不是额外的条规：

1. **证据高于叙事** — Agent 的自述不是验证；实际文件、命令结果、渲染输出才是。判断任何产物的正确性之前，先看实际产物。
2. **审查是对抗而非确认** — 审查者的职责是证伪，不是背书。如果能找到一条证据否定结论，审查就成功了。审查者独立读取原材料，不与生产者共享上下文。
3. **范围的唯一裁判是原始需求** — 一切产出追溯到用户最初的要求。没有需求覆盖的修改是越界，无论它有多合理。

这三条信念意味着：做最小充分的工作，每次修改后有实际证据支撑，审查者独立质疑一切关键结论。

## 流程选择

根据任务复杂度选择最小充分流程，不机械走全流程：

| 流程 | 适用场景 |
|------|----------|
| **轻量** | 小修改、简单查询——微设计→实施→自检→交付 |
| **仅设计** | 只需要方案不需要实施——调查→设计→审查→交付方案 |
| **执行已有设计** | 已有审批过的设计——校验设计→增量执行→自验证 |
| **设计并执行** | 完整任务，方案和执行都有风险——全流程 |

选择原则：**为任务匹配流程，而不是让任务适应流程**。不确定时选更充分的流程。

## 流程骨架

### 1. 明确任务

区分四类信息：
- **明确要求** — 用户说了什么（不可省略）
- **合理推断** — 从上下文可推导（应标注为推断）
- **待决事项** — 需要用户决策（只在显著改变范围、安全、兼容性或不可逆操作时才问）
- **明确排除** — 用户说不要什么（防止范围蔓延）

### 2. 调查现状

获取一手证据——阅读实际文件，运行实际命令，确认实际行为。调查深度与任务风险成正比。

关键原则：**设计之前必须先看清现状**。对现状的假设错误是大多数方案失败的根源。

### 3. 设计与审查

设计说明：问题、约束、方案、边界、异常路径、验证方法。讨论兼容性、迁移、安全、性能等仅在任务需要时。

**非轻量任务应进行独立设计审查**。审查者独立阅读需求和设计，不参与设计过程。

审查结论：
- `approved` — 可继续
- `revise` — 有证据支持的重大问题，应修订
- `blocked` — 缺用户决策或外部条件

最多两轮设计审查。第二轮仍有重大问题时，主 Agent 根据证据裁决或缩小范围。

### 4. 增量执行

- 拆成顺序明确、可独立验证的最小切片
- 一次完成一个切片，完成后以实际产物验证
- 设计假设被事实否定时，暂停并修订设计
- 同一失败连续两次时，停止并重新调查根因

**主 Agent 必须亲自检查每个切片的实际产物**，不能依赖执行 Agent 的自述。

### 5. 验证与最终复核

验证必须是事实性的——对实际产物运行，不是阅读自述或推断"应该没问题"。

验证手段按证据强度排序：
1. 自动化测试、构建、静态检查（最强）
2. 实际运行示例、数据对比
3. 手工检查、逐条验收核对（最弱但仍有价值）

执行完成后，由**新任独立审查者**检查原始需求、设计、实际产物、验证证据。最终审查同设计审查一样，最多两轮。

## 审查标准

### 问题等级

| 等级 | 定义 | 后果 |
|------|------|------|
| **重大** | 需求未满足、事实错误、方案不可行、数据损失、安全风险、兼容性破坏、不可恢复副作用、关键验证缺失 | 必须 `revise` |
| **重要** | 降低完整性/可靠性/可维护性，但不阻止交付 | 建议修复，不阻止交付 |
| **建议** | 表达、组织、风格、非必要优化 | 可采纳可不采纳 |

### 审查原则

1. **对抗而非确认** — 任务是找出为什么它是错的，不是为什么它可能对。
2. **证据驱动的疑问** — 每个质疑都有具体位置和实际证据，不是笼统的"可能有问题"。
3. **能具体指出错误的怀疑才是有效的审查** — 不能指出具体问题的"感觉不对"不是审查结论。
4. **不经手产物** — 审查者只写报告，不修改被审查的内容。

### 重大问题的报告格式

每个重大问题至少包含：**具体位置**（文件、行号）、**实际证据**（不是推测）、**影响**（为什么是重大的）、**最小修复方向**（不替代实现，只说方向）。

## 独立 Agent 规则

详细规则见 [reference/agent-rules.md](reference/agent-rules.md)。核心约束：

- **主 Agent** — 维护范围，检查实际产物，承担最终结论。不可委托最终判断。
- **生产者** — 只做指定切片，不修改无关文件，不启动其他 Agent。
- **审查者** — 独立读取原材料，只写审查报告，不修改产物，不根据预期结论审查。

## 降级处理

独立 Agent 不可用时，主 Agent 执行显式第二遍审查（重新阅读原始需求和实际产物，从审查者视角重新审视），并说明采用降级模式。Agent 输出异常时重试一次，之后主 Agent 接管。

## 交付

先说结论，再说过程：
1. 完成了什么，是否满足原始需求
2. 关键决定和产物位置
3. 验证方法与结果
4. 未解决风险、假设和未覆盖范围

**验证失败时不得宣称完成**。若失败与本次变更无关，给出相应证据。
