# 渐进式创作工作流

根据核心协议确定本轮结果类型。本 Skill 只规定音乐创作和发展方法，工具、提交与失败升级以核心协议和宿主
最新状态为准。

1. 用户仍在选择方向或明确要求先看方案时，用自包含计划明确核心材料、整体结构、配器和发展方向。用户明确
   要求试听核心材料时可以先生成短草稿；草稿可以短于目标时长，但必须如实标记。
2. 根据试听反馈定位问题范围；局部反馈只修改相关段落，整体反馈允许重审全曲。重复材料必须承担建立、强化、
   变化或回归作用，长段落不能主要依靠同一短动机原样循环。不要要求用户逐段试听或逐段确认。
3. 完整候选应有可感知的开始、发展和结束，并具有足够内容量；高潮应来自材料演变、声部进入退出和前后对比，
   不能只靠提高速度、音量或音区。
4. 长篇创作中，如果边界清晰的音乐设计、Alda 实现或只读复核能降低职责切换，可按需调用 `delegate`；不要
   预设固定 Worker 或段落分组。宿主触发诊断升级时必须遵循 Reviewer 边界。
5. 目标时长下限不少于 120 秒时，先建立 4–10 段 `form_plan`，按秒分配连续预算，并为每段指定音乐职责、
   材料动作和能量；在源码中按同序定义 `%section_<id>`。tempo 与小节数只用于初始布局。时长不足时增加有
   职责的变奏、对比、发展、再现或尾声，不把短循环按比例复制，不用持续铺满所有声部来优化时间线诊断。
6. 客观检查用于调整材料，不代替听觉判断。时间线、事件空档、声部尾差和局部静音可以是有意的音乐决策；
   不要为了让诊断整齐而消除休止、持续铺满声部或强制同时结束。

修改已有结构化长篇时声明 `edit_scope`：明确指向段落、乐器或参数时使用 `local` 并只修改相关段落；指向
整体听感、艺术性、编排、结构或另一种诠释时使用 `global`。适合少量唯一文本替换的局部修改先用
`inspect_score` 取得基线 `source_hash`，再优先使用
`inspect_alda_patch`。完整试听仍是默认路径；只有定位问题或比较修改前后时才按 Marker 播放带上下文的局部
窗口，局部播放不是接受候选的门禁。
